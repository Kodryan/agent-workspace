# Task Notes

Use task notes for work likely to span repositories or sessions, or when the user asks.

## Start

- Copy `_template.md`; name the note for the ticket or a short task name.
- Build the spec from the request and linked primary sources. Mark gaps unknown.
- The spec sets scope; ask before materially expanding it.

## Maintain

- Keep notes concise. Update meaningful findings and decisions with links to code, tickets, documents, or other evidence.
- Separate decisions, hypotheses, and open questions. Make `Next step` clear enough for another session.
- Verify changing implementation details in current code.

## Finish

- Record outcome and follow-up; keep task research here.
- Move lasting feature or initiative context to `../Projects/` and repository relationships to `../Repositories.md` only when needed; add routes to `../AGENTS.md`.
- Do not copy secrets, tokens, credentials, or large source excerpts into notes.
